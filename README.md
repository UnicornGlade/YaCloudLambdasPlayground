# Unicorn Glade — облачный счётчик

Учебный монорепозиторий: Nuxt 4 + Nitro `aws_lambda` + PostgreSQL. Цель — воспроизводимый деплой в Yandex Cloud одной командой, проверка, логи и откат.

## Текущий статус

**Подготовлен первый, локальный этап. В облако ещё ничего не развёрнуто.**

Реализованы:

- статическая Nuxt-страница с глобальным счётчиком и местом для ссылки на большой архив;
- `GET /api/health` — проверка приложения и версия, без обращения к БД;
- `GET /api/ready` — проверка доступности БД и инициализации счётчика;
- `GET /api/counter`, `POST /api/counter` — чтение и атомарное увеличение;
- миграции с транзакцией, advisory lock и проверкой контрольных сумм;
- JSON-логи с идентификатором запроса и версией;
- сборка статики отдельно от ZIP-функции; CommonJS-обёртка для Yandex;
- unit-тесты, тест настоящей Lambda-сборки и отдельный интеграционный тест PostgreSQL.

**Terraform, облачный деплой, сертификат, DNS, получение облачных логов и откат — следующий этап, не реализованы.** План: [docs/DEPLOYMENT-PLAN.md](docs/DEPLOYMENT-PLAN.md).

## Что блокирует облачный этап

При первоначальной проверке окружения:

1. `yc` установлен, но сохранённый OAuth-токен недействителен/истёк. Нужно заново выполнить `yc init` в своём терминале. Не отправлять токены в чат и не добавлять их в Git.
2. `unicornglade.tech` уже имеет A-запись `178.210.92.188`, DNS — `ns3.nic.ru`, `ns4.nic.ru`, `ns8.nic.ru`. Записи **не менялись**. Предлагается `playground.unicornglade.tech`; имя ещё нужно подтвердить.
3. Terraform пока не установлен.
4. Docker установлен, но текущий процесс не имеет доступа к его сокету, и плагин `docker compose` отсутствует. Поэтому интеграционный тест с настоящим PostgreSQL пока не выполнен. Не используйте `chmod 666 /var/run/docker.sock`.

Доступ к Docker можно настроить отдельно (предпочтительно rootless Docker). Это не блокирует тесты приложения без БД и последующий тест с Managed PostgreSQL в облаке. Добавление пользователя в группу `docker` даёт фактически root-доступ — это осознанное административное решение владельца машины, а не действие агента по умолчанию.

## Быстрая проверка без облака и Docker

Требуются Node.js 22.19+ из поддерживаемой ветки (см. `.nvmrc`), npm и `zip`.

```bash
npm ci
npm run check
```

`check` проверяет типы, unit-тесты, собирает проект и вызывает готовую Lambda-функцию с событием в формате Yandex API Gateway v2. Для проверки автономности сборка копируется во временную директорию вне репозитория.

Эта проверка **не означает**, что функция уже проверена в реальной среде Cloud Functions, и **не проверяет PostgreSQL**.

## Локальная разработка с PostgreSQL

После настройки доступа к Docker и установки Compose:

```bash
cp .env.example .env           # только если своего .env ещё нет
npm run db:up
npm run db:migrate
npm run dev
```

Открыть адрес, напечатанный Nuxt (обычно http://127.0.0.1:3000).

В другом терминале:

```bash
npm run smoke
npm run smoke -- --increment  # явно разрешает один реальный инкремент
```

`smoke` по умолчанию только читает данные. Можно передать URL:

```bash
npm run smoke -- https://playground.unicornglade.tech
```

Последний пример начнёт работать только после облачного деплоя и DNS. Если задан `ARCHIVE_URL`, выполняется HEAD-проверка архива без скачивания большого файла.

### Интеграционный тест БД

Тест использует отдельную временную схему, выполняет миграцию дважды, делает 50 конкурентных инкрементов и проверяет сохранность значения при новом подключении. При завершении удаляет только свою временную схему.

```bash
TEST_DATABASE_URL=postgresql://counter:counter@127.0.0.1:54329/counter npm run test:db
```

Без `TEST_DATABASE_URL` тест **пропускается**, а не считается проверкой БД. Разрешены только loopback-адреса, чтобы случайно не нагрузить облачную БД.

```bash
npm run db:down  # останавливает локальный PostgreSQL; Docker volume с данными сохраняется
```

Не добавлять `-v`, если данные нужны.

## Сборка

```bash
npm run build
```

Результат:

```text
.artifacts/
  site/             # только эти файлы предназначены для бакета сайта
  function/         # распакованный сервер и index.js, точка входа index.handler
  function.zip      # пакет Cloud Functions
  release.json      # версия приложения, SHA-256 ZIP, формат payload
```

Nuxt работает с `ssr: false`, `/` явно пререндерится в `index.html`, а API сохраняется в серверной сборке Nitro. Обычный `nuxt generate` не заменяет эту сборку двух артефактов.

По умолчанию версия состоит из Git revision (или `local`, если коммита ещё нет) и времени сборки. Для заданной версии:

```bash
APP_VERSION=v0.1.0 npm run build
```

В API Gateway необходимо **явно** задать `payload_format_version: '2.0'`. Обёртка отклоняет формат v0.1 по умолчанию. AWS response streaming выключен. `/api/health` проверен локально через эту обёртку, но совместимость облачного загрузчика ещё нужно проверить реальным вызовом.

## Конфигурация и безопасность

- `.env` — только локально, исключён из Git.
- `DATABASE_URL` — серверный секрет, не `NUXT_PUBLIC_*`. Query-параметры в нём запрещены, чтобы они не переопределяли TLS/host.
- В облаке используется TLS с проверкой сертификата: `PGSSLMODE=verify-full`, `PGSSLROOTCERT` — путь к CA Yandex. Отключить TLS разрешено только для localhost.
- Пул ограничен двумя соединениями на экземпляр функции; в облаке дополнительно ограничим число экземпляров/вызовов.
- `NUXT_PUBLIC_DOWNLOAD_URL` — публичный HTTPS URL. Он встраивается в статическую сборку: изменение требует пересборки сайта, а не только переменной функции.
- API возвращает `Cache-Control: no-store`. Кеширование HTML и хешированных JS/CSS настраивается отдельно при публикации в S3.
- BIGINT передаётся строкой, чтобы не терять точность JavaScript.
- Счётчик публичный. Лимиты API Gateway ещё не настроены, поскольку облачная инфраструктура ещё не создана.
- POST не повторяется автоматически. При сетевом сбое запись могла успеть сохраниться; интерфейс предлагает сначала обновить значение. Семантика exactly-once/idempotency keys пока не реализована.
- Деплой и миграции не должны сбрасывать счётчик. Не изменять уже применённые миграции — добавлять новые.
- Не загружать репозиторий целиком в публичный бакет. Никогда не публиковать `.env`, `.git`, Terraform state или серверную сборку.

## Навигация

- `app/app.vue` — страница.
- `server/api/` — HTTP API.
- `server/lib/` — SQL и безопасные настройки подключения.
- `migrations/` — схема данных.
- `scripts/` — локальные операции, сборка и проверка.
- `deploy/function/index.js` — исходник обёртки для облачного загрузчика.
- `tests/` — тесты.
- `docs/DEPLOYMENT-PLAN.md` — план инфраструктуры и критерии готовности.
