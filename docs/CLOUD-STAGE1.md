## Созданные ресурсы

В `infra/application/` описаны:

1. Бакет `unicornglade-site-b1gh1fk7hbuj5hu9tujb`: публичное чтение файлов, без публичного списка и конфигурации. Загружены только `.artifacts/site`, не репозиторий и не серверный ZIP.
2. Функция `playground-api` (`d4eguocjn75tc3nmt4oe`): Node.js 22, 256 МБ, timeout 10 секунд, concurrency 1, entrypoint `index.handler`, без переменных БД и без сервисного аккаунта с доступом к облачным ресурсам. Metadata endpoints выключены.
3. Сервисный аккаунт шлюза `playground-gateway`: имеет только `functions.functionInvoker` на конкретную функцию. Постоянных ключей нет.
4. IAM binding на функцию: анонимный прямой вызов запрещён (проверен 403).
5. Scaling policy: максимум один экземпляр и один одновременный запрос **на зону**, для тегов `live` и `$latest`. Это не глобальный лимит расходов.
6. API Gateway `playground` (`d5dnv6ig2a6jhr14ffdf`): `/` и файлы из S3, `/api/{path+}` в приватную функцию с `payload_format_version: '2.0'`. Для статики доступны GET и HEAD.
7. Группа Cloud Logging `playground-application` (`e23qn8to2a9pf9go6s92`): хранение 24 часа. Функция пишет INFO+, шлюз WARN+.

State: `terraform/application.tfstate` в существующем приватном backend. Bootstrap и общая DNS-зона остаются в собственных state.

## Повторить публикацию

```bash
npm ci
npm run check
npm run infra -- application init
npm run infra -- application plan
# Проверить план перед применением.
npm run infra -- application apply
npm run publish:site
npm run smoke -- https://d5dnv6ig2a6jhr14ffdf.fovt0b64.apigw.yandexcloud.net --without-db
```

Terraform единолично управляет версиями функции и тегом `live`; не обновлять их параллельно через CLI. Хеш ZIP определяет необходимость новой версии. Между plan и apply нельзя пересобирать ZIP: обёртка проверяет его хеш и отказывается применять несовпадающую сборку.

`publish:site` не принимает произвольный путь/бакет, проверяет соответствие версии опубликованной функции, запрещает скрытые файлы, symlink и неизвестные расширения, загружает index.html последним. Старые assets не удаляются. HTML/JSON имеют `no-cache`, хешированные JS/CSS — длительный immutable cache. Обновление функции и сайта не атомарно; полноценный release/rollback-процесс остаётся следующим этапом.

## Диагностика только для чтения

```bash
npm run cloud:status
npm run cloud:logs
```

Статус читает metadata шлюза, статус сертификата и `/api/health`. Логи ограничены последними 15 минутами (кроме последних 10 секунд), 30 записями приложения, 64 КБ и таймаутом 30 секунд. Эти команды не читают Terraform state, не создают постоянные ключи и не запускают apply. Используют текущую авторизацию `yc`; отдельный диагностический аккаунт с read-only IAM-ролями ещё не создан.

Для поиска по request ID вручную можно добавить фильтр в ограниченную read-only команду `yc logging read`. Не выгружать журналы без ограничения периода и объёма. Учитывать объявленный переход Cloud Logging к Monium до II квартала 2027 года.

## Подключение собственного домена — выполнено 22 сентября

`enable_custom_domain` теперь постоянно включён в конфигурации. Применён план: одна CNAME создана, шлюз обновлён, без удалений. Корневые записи не менялись. Ниже сохранена последовательность выполненных действий.

1. Проверить `npm run cloud:status`, дождаться `ISSUED`.
2. В `infra/application/versions.tf` изменить default у `enable_custom_domain` на `true`, чтобы решение сохранялось в конфигурации, а не только в окружении одного запуска.
3. Выполнить application plan: ожидается обновление шлюза и создание одной CNAME `playground.unicornglade.tech` на технический адрес. Общая зона и корневые записи не меняются.
4. Проверить и применить план, затем выполнить smoke `--without-db` на https://playground.unicornglade.tech.

Проверочная CNAME сертификата сохранена для автоматического продления. Удаление/пересоздание сертификата не потребовалось. Следующий шаг — [план PostgreSQL](DATABASE-PLAN.md), пока без apply.

## Стоимость и ограничения

Перед созданием показан план: 7 новых ресурсов, без удалений. При небольшой учебной нагрузке ожидаются около нуля/нескольких рублей дополнительных расходов, если бесплатные квоты не заняты другими проектами; существующая DNS-зона оплачивается отдельно (~43 ₽ за 30 дней плюс DNS-запросы).

Тарифы России с НДС:
- API Gateway: первые 100 тысяч запросов/месяц бесплатно, далее 142,30 ₽/миллион.
- Cloud Functions: первый миллион вызовов и 10 ГБ·час бесплатно, далее 18,97 ₽/миллион и 6,48 ₽/ГБ·час.
- Object Storage, Cloud Logging и исходящий трафик — по их тарифам/бесплатным квотам.

Резервируемых экземпляров, БД и VM нет. Квоты Cloud Functions прочитаны, ресурсы созданы без повышения квот. Отдельная проверка биллингового аккаунта и бюджетные уведомления ещё не реализованы.

Важно: прежние расширения rate limit API Gateway объявлены неподдерживаемыми. Не добавлены как фиктивная защита. Для ограничения частоты и защиты от злоупотреблений нужен отдельный этап с актуальной интеграцией Smart Web Security. Ограничение экземпляров функции, размера бакета и срока логов не является жёстким бюджетным лимитом.

Источники: [Functions pricing](https://yandex.cloud/ru/docs/functions/pricing), [API Gateway pricing](https://yandex.cloud/ru/docs/api-gateway/pricing), [rate limit](https://yandex.cloud/ru/docs/api-gateway/concepts/extensions/rate-limit), [проверка домена](https://yandex.cloud/ru/docs/certificate-manager/concepts/challenges).
