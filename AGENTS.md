# Правила работы с проектом

## Фактический статус

Сначала читать `README.md` и `docs/DEPLOYMENT-PLAN.md`. Пока реализован локальный этап, инфраструктура Terraform и облачный деплой ещё не реализованы. Не выдавать локальную проверку AWS payload за успешный вызов в Yandex Cloud.

## Проверки

- `npm ci` — воспроизводимая установка.
- `npm run check` — типы, unit-тесты, сборка, локальные тесты Lambda.
- `npm run test:db` без TEST_DATABASE_URL пропускает тест. Пропуск не является проверкой PostgreSQL.
- Интеграционный тест разрешён только с отдельным localhost PostgreSQL и явным TEST_DATABASE_URL.
- `npm run smoke -- <url>` по умолчанию read-only. `--increment` действительно меняет глобальный счётчик и требует соответствующего намерения пользователя.

## Безопасность

- Не читать и не печатать OAuth/IAM-токены, `.env`, `~/.config/yandex-cloud/config.yaml` или Terraform state целиком.
- Для проверки yc использовать команды получения конкретных несекретных параметров или read-only API. При истёкшем токене попросить владельца выполнить `yc init`; не просить прислать токен в чат.
- Корневой домен unicornglade.tech уже имел A-запись 178.210.92.188. Не заменять её без подтверждения. playground.unicornglade.tech пока только предложение.
- Перед первым созданием платных ресурсов показать план и стоимость. Не выполнять destroy или удаление данных ради устранения ошибки деплоя.
- Не выполнять административные изменения Docker/прав сокета без согласования. Особенно не делать сокет доступным всем.
- Не запускать миграции из публичного HTTP endpoint.
- Не менять применённые SQL-миграции. Не сбрасывать счётчик при релизе.
- В публичный бакет загружать только `.artifacts/site`, никогда не репозиторий целиком.

## Архитектура

- Nuxt 4, ssr=false, явный пререндер `/`, Nitro preset aws_lambda, без response streaming.
- API Gateway payload_format_version=2.0; обёртка deploy/function/index.js копируется в CommonJS-пакет.
- Backend и frontend — отдельные артефакты одной сборки.
- DATABASE_URL только на сервере; проверять TLS в облаке, не использовать rejectUnauthorized=false.
- Счётчик BIGINT передаётся строкой. Инкремент одним UPDATE ... RETURNING, без read-modify-write и автоматических повторов POST.
- Пул PostgreSQL ограничен. В облаке понадобятся дополнительные ограничения масштабирования функции.
- Для облачной диагностики в дальнейшем предоставить отдельные read-only команды с ограниченным периодом/объёмом логов, не административные ключи по умолчанию.
